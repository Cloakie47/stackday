For developers

Trigger bot and API routes

A small bot presses the buttons the contracts already let anyone press: due paydays, due recurring buys and expired gift refunds. The API routes handle sign-in, accounts, chat, gifts and research, and the site keeps working when they are switched off.

{{PLAIN}}

Blockchains do not act on their own: someone has to send a transaction to make a scheduled payday or a weekly buy happen. Stackday's trigger bot does that once each weekday. It cannot change what you set up and it holds none of your money; its wallet only pays the network fee.

The trigger bot

GET /api/keeper runs on a Vercel cron at 16:00 UTC, Monday to Friday (0 16 * * 1-5), which is 11:00 New York time in winter, matching the slot recurring buys are set to.

  • Secrets (names only): CRON_SECRET (at least 16 characters, compared in constant time), KEEPER_PRIVATE_KEY (a gas-only wallet), optional KEEPER_RPC_URL. Recurring buys also need the database settings and the recurring_plans table.
  • Registering a plan: saving a recurring buy calls POST /api/keeper/register with the wallet and asset. No sign-in is needed, because the route checks that the plan really exists on chain.
  • Only the founder's Vercel project runs this cron, and only once CRON_SECRET and KEEPER_PRIVATE_KEY are set there. Without them nothing runs automatically, and due items wait until someone presses the button in the app.

Sign-in

  1. The browser asks POST /api/session/nonce for a single-use code (16 random bytes, stored for 10 minutes).

  2. The wallet signs a Sign-In with Ethereum (EIP-4361) message with the site domain, chain 84532, the code and a 10-minute expiry.

  3. POST /api/session checks the domain, chain and times, deletes the code in one statement (so it can never be used twice), then verifies the signature. Smart contract wallets work too.

  4. The first sign-in creates the profile. The session is an HttpOnly, SameSite=Lax cookie holding the wallet and an expiry, signed with HMAC, valid for 7 days.

Database tables

From supabase/schema.sql, every table with row level security on and no public policies: profiles, sign_in_nonces, employees, attendance, businesses, rate_limits, recurring_plans, gifts, and the research tables research_runs, research_notes, research_market, research_weekly, research_weekly_sections, research_scores, research_portfolios, research_entitlements, research_payments and research_onchain_tail.
