Research engine

How the daily note and the Monday report are produced: which models run, how a weekly report fits into Vercel's time limits, how reviewers approve it, and what stops a bad run.

{{PLAIN}}

A computer program collects market data and works out every number. AI models then write about those numbers, other passes check their work, and a person signs off before it is published. If anything goes wrong or gets too expensive, the run stops and publishes nothing.

The Monday run, step by step

A full weekly report is too long for one serverless call (Vercel Hobby stops a function at 300 seconds), so the cron calls the weekly route once an hour and each call does one step.

The daily run

  1. If the market was closed, carry the last note forward.
  2. Gather data in code, then a triage pass on the cheaper model.
  3. Big movers and answers that fail checks get a second pass on the stronger model.
  4. A risk check in code removes unsupported claims and caps conviction. Buy zone and invalidation levels are computed in code.
  5. If more than two assets end with no reading, nothing is written.

The score job at 23:00 UTC grades notes after 1 and 5 trading days (direction, levels, facts share) and keeps calibration per conviction level. Reviewers add a 1 to 5 grade.

Safety and honesty rules in code

  • Facts first. Every number is a fact with an id, a source, a link and a time (web/lib/research/data). The model never calculates a price, an indicator or a level, and a claim without a fact id is removed.
  • Untrusted text. Headlines, filings and web text go inside an <untrusted_news> block and through an injection screen; anything that reads like instructions to an AI is dropped and logged. Headline links are checked against a whitelist of outlet host names.
  • No money powers. The engine has no wallet, no keys and no tool that sends transactions.
  • Strict JSON. Output is parsed and validated against a schema before rendering.
  • No look-ahead. Bars are cut at the run time and macro series are used only from their real release day, so a report and any backtest only use data that existed then.
  • Reproducible. Model ids, prompt version and a hash of the data are logged per run.
  • Fail closed. A run that fails or hits a cap writes nothing, and can send an alert to RESEARCH_ALERT_WEBHOOK_URL.
  • Labels. Every page and report carries the research disclaimer; the weekly report carries the Beta label until the quality bar holds.
